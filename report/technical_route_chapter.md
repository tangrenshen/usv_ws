# 整体技术路线

> 本节把标定、拼接/BEV、检测/融合三条支线串成一个系统，说明各章节技术方案
> 之间的依赖与协作关系，同时集中说明贯穿全系统的几个关键设计决策及其理由。
> 各支线的详细验证数据见对应专章：标定方法、拼接重投影误差、检测/轮廓精度
> 均已单独成章；BEV图像质量评估与融合精度尚未开始，待赛会口径答复。

## 2. 各环节的角色与关键设计决策

### 2.1 自标定是外参的唯一来源，且带内置可信度判定

系统不依赖陆地标定，外参完全来自运行时自标定（环状拓扑发现+粗精两级求解，
方法与验证见标定章节）。与常规方案的关键区别在于：自标定的输出不是"一个
外参解"，而是"一个外参解 + 这个解在多大程度上可信"——通过独立留出地标
验收（而非内部残差）判断，这一判断结果直接决定第2.2节的默认策略。

### 2.2 为什么默认名义外参、不做在线热替换

标定章节第3节已证明：在竞赛级扰动幅度（±0.5m/±10°）下，六路Airy雷达中
right支可稳健收敛（独立验收0.045m），但back/left支存在几何层面的可辨识性
边界，收敛判据满足不代表解正确。基于这一发现，系统设计上采用保守默认：
启动即以名义外参运行全链路，自标定在独立线程后台持续尝试，只有**同时满足
内部收敛判据与独立地标验收**才热替换生效外参——这一双重门槛直接针对
"内部残差下降不代表解正确"这一已被数据证实的陷阱设计，不是随意加严。

### 2.3 为什讨论移出生产路径：诊断与生产解耦

`ImageStitcher::optimizeExtrinsics`/`evaluateCameraPair`（拼接重投影误差
诊断）默认关闭，通过`enable_stitching_diagnostics`参数按需启用。原因是
ORB+RANSAC特征匹配单帧耗时100ms+，会占用BEV分支近一半的处理时间，影响
5Hz的标称发布周期。诊断路径与`blendBEV`的实际渲染结果完全解耦（诊断输出
不参与、也不影响BEV图像本身），因此可以安全地按需开关，不牺牲生产路径的
实时性来获取诊断数据。本session验证：在算力充足的环境下，开启诊断对BEV
实际发布频率无可测量影响（4.92-4.96Hz，与关闭诊断时的4.6-4.98Hz基本一致），
但该开关设计的价值不依赖具体硬件表现——不同算力环境下都能安全回退。

### 2.4 图像支路与点云支路相对独立，融合发生在检测结果层面

图像支路（IPM+拼接）产出BEV鸟瞰图，服务于评分细则指标1（拼接重叠误差）
与远期的虚拟增强场景展示；点云支路（多雷达融合+聚类+分类）产出四类目标
的结构化检测结果，服务于指标3、4（位置/轮廓精度、遗漏率）。两条支路共享
同一份外参（第2.1节），但计算路径独立，互不阻塞——这也是2.3节诊断开关
可以独立控制、不影响点云支路检测实时性的原因。视觉辅助确权（颜色验证）
是两条支路之间设计上唯一的耦合点：点云检测到候选目标后，投影回对应
鱼眼图像做颜色校验，提升分类置信度，但不改变候选目标的空间位置——即
视觉信息只做"确权"，不做"定位"，避免引入镜头畸变模型误差污染空间精度。
**需要明确的是，该耦合目前是架构设计，尚未启用**：`fuseVisionColor`/
`verifyPillarColor`/`verifyBlockColor`三个确权接口在当前`main.cpp`里
没有调用点，是预留但未接入生产链路的代码（见拼接重投影误差章节第6.3节
的负结果排查）。这意味着现阶段两条支路在运行时是完全独立、互不耦合的
——图像/BEV支路的任何缺陷（如该章节记录的IPM投影伪影、扰动下的接缝
退化）都不会传导到检测精度，这是本次排查确认的结果，而非架构设计的
必然保证。

### 2.5 四类输出话题选择MarkerArray而非PoseArray的接口考量

`*_check`系列话题（buoys_check/boats_check/pillars_check/blocks_check）
采用`visualization_msgs/MarkerArray`而非任务书原文示例的`PoseArray`——这是
赛会后续明确的接口变更（要求携带长宽高），本方案已完成迁移并做了发布语义
设计：每帧先发一个`DELETEALL`动作清空上一帧的marker，避免陈旧marker残留
在下游订阅者的显示/记录里；只有`action=ADD`的marker是当帧真实目标，`stamp`
取首个真实marker的时间戳（无真实目标的帧才退化为使用DELETEALL自身时间戳）。
这一设计使得下游消费者（包括自测报告用的离线评估脚本）可以用统一、明确的
规则从原始消息流里还原出"这一帧究竟检测到了什么"，不依赖对发布时序的
隐式假设。

## 3. 与评分指标的对应关系

| 系统环节 | 对应评分指标 |
|---|---|
| 自标定方法 + 可信度判定 | 感知系统标定方法（专家评分） |
| 图像支路：IPM+拼接 | 拼接重叠像素（重投影误差） |
| 点云支路：融合+聚类+分类 | 周围目标识别精度、遗漏率 |
| 前向+周围融合 | 感知融合精度 |
| 全系统在Ubuntu环境的可部署性 | 技术可行性（报告评审） |

三条支线（标定、拼接、检测/轮廓）各自的详细方法与验证数据见对应专章；本节
仅说明它们如何组成一个协同工作的系统，以及跨支线共享的关键设计决策为何
如此选择。
