# 结论与局限

> 本节汇总环境感知模块的完成情况，明确区分三类不同性质的条目：**已达成**、
> **经论证后主动决定不做**（工程判断，不是缺口）、以及**真实存在的局限**
> （如实交代，并给出推进所需条件）。这一区分本身对应技术可行性评分对
> "可实现性分析"的要求——不能把判断力和未完成混为一谈。

## 1. 已达成

- **标定方法**：不依赖陆地标定，基于场景公共地标的环状拓扑自动发现（
  非预设配对）+ 粗精两级求解；闭环一致性四项独立指标验证（旋转残差
  0.87°、平移残差0.163m）；right支独立留出地标验收0.045m，证明该数据
  条件下至少部分传感器可被稳健标定；可辨识性边界经七轮独立方法交叉
  验证确认为几何层面固有限制，而非数据/方法缺陷。
- **拼接重投影误差**：0.9998px（5次独立随机世界初始化，算术平均，
  按评分细则原文方法论）；两层稳健聚合方法论（单run内中位数/截尾均值
  + 跨run算术平均）经数据论证，"平均"一词的字面歧义已正面回应。
- **近距离(0-20m)目标尺寸估计基本无偏**：跨5次独立初始化验证，无系统性
  方向偏置。
- **周围目标识别（buoy/pillar/block）在5次独立随机场景下的表现区间**：
  召回39.6%~73.4%、误检11.0%~52.0%，并定位了方差的主要驱动因素（立柱
  中位距离与召回率强相关，r=-0.95, n=5，与已量化的距离衰减机制吻合）。
- **一套经过验证的测试方法论**：同场景重复测试与跨场景独立测试测量的
  是两个不同的量，前者系统性低估真实方差（见实验分析章节）；这一发现
  本身影响了对本方案历史结论置信度的表述，也定型了"效应量必须显著
  超过已知方差才进入生产路径"这一判断标准。

## 2. 经论证后主动决定不做——工程判断，非未完成

以下三项**不是尚未完成的工作**，而是有具体量化依据支撑的主动决定，
详见实验分析章节第5节：

- **20-40m距离段不引入尺寸补偿**：跨5次独立场景验证，偏差方向本身
  不一致（-25.9%~+10.7%），任何固定方向的系数都会在部分场景下适得
  其反。
- **40m+距离段不引入尺寸放大补偿**：效应真实且方向/量级跨场景一致
  （-38.1%~-53.1%），但所需约2倍放大系数会将已知的跨场景方差（约15个
  百分点）等比例放大到最终结果上，补偿操作本身的风险超过收益。
- **boat检出率问题不再投入时间深挖评估工具**：本session已确认评估
  方法论没有缺陷（残差异常源于检出目标身份切换，非时钟或检测漂移），
  第3节将说明为什么检出率本身仍是需要交代的真实局限。

## 3. 真实局限：如实交代，并给出推进所需条件

- **boat（唯一动态类别）检出率约15-18%，是感知模块当前最大的单一
  短板**。本轮已用簇级诊断把成因定位到具体判据（见检测与遗漏率章节
  第5节）：距离与运动两个直觉解释均被数据证伪——船只反而是四类中
  距离条件最好的一类（中位24.8-29.2m，5次运行约14000个实例无一超出
  60m量程），速度中位仅1.0m/s、每帧位移小于船体自身尺寸；**真正的
  主因是簇已形成、形状与高度判据全部通过，仅因点数不足（10-14点
  vs `boat_min_pts=40`／兜底25）被丢弃**，该门槛注释所依据的"真实
  船只148-1365点"这一经验前提，只在近距离采样充分时成立。
  **推进条件**：门槛调整的代价尚未测量——噪声碎片点数（8-12）与
  待挽回真船簇点数（10-14）分布高度重叠，而boat误检率本就是四类
  最高，需先完成召回与误检双侧A/B，效应量明显超过已知跨场景方差
  才可进入生产路径。此外视觉软证据（`fuseVisionColor`等尚未接入
  boat）仍是一条独立的正交路径，两者不互斥。
- **pillar/block在40m+距离段召回与尺寸精度均为已知短板**，成因已定位
  为几何近端面效应（第4节说明这是传感器配置的固有限制，而非算法缺陷）。
- **buoy轮廓精度从未验证——但2026-08-31查证后，原先记录的阻塞理由
  在本赛题场景下并不成立。** 此前记为"round型（球，直径0.5m）与marker型
  （套环，直径0.65m）两种物理尺寸相差约30%，且GT话题与检测输出均不携带
  类型字段，无法确定某个实例是哪型"。实际核对世界SDF：42个浮球全部是
  `mb_round_buoy_black`（21个）与`mb_round_buoy_orange`（21个），**是同一
  种物理模型、只有颜色不同**，模型定义为球体`<radius>0.25</radius>`，即
  直径0.5m，**该场景样本中不存在第二种尺寸**。因此"类型不可判别"这一阻塞
  在此不适用，buoy轮廓可按单一canonical直径0.5m直接验证。
  **适用范围必须写明**：这是对**当前已录制场景样本**的观察，不是对所有比测
  场景的保证——赛会说明5次测试"物体数量会轻微调整"，若某次跑测中出现marker
  型浮球（套环，直径0.65m，与round型相差约30%），尺寸真值随之改变，原先记录
  的类型判别问题会重新成立。因此实现时应按每次运行各自的世界SDF建表（见下条），
  而不是把0.5m写死成常数；建表流程本身对两种型号都成立，不需要额外工作。
  **推进条件**：并入下面"尺寸真值来源"那一条统一处理即可。
- **尺寸真值必须取自世界SDF，不能取自GT话题（2026-08-31确认）**。四类GT
  话题（`/world/obstacles/*`）只发布位置，**完全不携带任何尺寸字段**；
  立柱的SDF pose中z恒为0，连高度都读不到。而世界SDF里每个实例的几何是
  完整的：立柱`<cylinder><radius>0.8</radius><length>h</length>`且**高度
  逐个随机**（p2区`uniform(5,10)`共35根、p3区`uniform(8,15)`共1根），浮球
  球体半径0.25，船只为roboboat01/02。赛会新口径要求"长宽高误差绝对值之和"，
  其中高度项没有SDF就无从算起。**推进条件**：按每次运行的
  `perception_user_random_<seed>.sdf` 建立逐实例尺寸真值表，再与检测输出
  按位置匹配。该文件由launch自动生成、种子记录在launch日志中，可追溯。
- **z轴（高度方向）尺寸精度未验证**。**推进条件**：需要先统一检测侧
  （水面分位数滤波估计）与GT侧（模型几何裁剪基准）的水面高度基准，
  否则测的是两个水面估计之间的差值，不是真实高度误差。
- **感知融合精度整体未开始**。**推进条件**：无法在现有录制数据上
  建立基线，因为(a)没有精准点云真值话题，只能等比测现场提供；
  (b)`lidar_check`融合点云是否应包含本船自身船体点这一口径问题
  尚未得到赛会答复，会直接影响融合算法的实现方式，不应在口径确认前
  投入实现。
- **BEV与俯视相机的像素级误差评估未开始——这是一整块全新工作**。赛会已
  明确评价方式为"拼接结果与俯视摄像头的成像数据进行像素误差测评"，且含
  目视评价成分。**注意这与本方案已完成的0.9998px不是同一个量**：那个测的是
  相邻相机BEV瓦片之间的重投影误差，可能不对应任何评分项。
  **一个必须在方法设计里处理的几何问题**：俯视相机（base_link上方11.95m、
  正下方90°、HFOV 120°、1280×1280、理想针孔无畸变）**本身不是正交真值**，
  它对有高度目标同样有中心投影视差，拉伸系数 1/(1−h/11.95)：浮球1.048、
  浮块1.072、船只1.035都还好，但**立柱高5.11~11.68m，拉伸系数高达
  1.85~2.88**。场景中立柱有36个，是数量第二多的类别，整图一起算时立柱区域
  会主导误差，而这部分误差**主要来自参考侧而非本方案的BEV**。
  **推进条件**：(a) 已完成——俯视话题验证有数据、内参已取得、5次带俯视的
  数据集已录制（`bags_5run_v2`）；(b) 待定——采用分区域评价（把立柱区域
  单独标注或排除，并在报告中说明理由）还是显式扣除已知视差成分；
  (c) 建议向赛会确认：参考基准对高目标存在2倍以上几何偏差这一点是否在
  评分设计中被考虑过。另注：俯视图地面分辨率3.23cm/px，比BEV的2.00cm/px
  更粗，重采样方向与插值方式需固定并写明。

## 4. 面向后续工作：区分"有明确技术路径"、"已验证的负结果"与"受限于
传感器配置本身"

**有明确技术路径，值得后续投入**：
- boat点数门槛的双侧A/B（第3节）——成因已定位到具体判据，剩下的是
  量化代价，是本轮新增的、目前最接近可执行的一条；
- boat的视觉软证据扩展（第3节）；
- **buoy轮廓验证**——原先列的"双峰自判别"思路已不再需要：查证世界SDF后
  确认场景中只有一种物理浮球模型（球，直径0.5m），不存在需要区分的第二
  种尺寸（第3节）。剩下的工作是建立SDF逐实例尺寸真值表，与pillar/block
  共用同一套流程。

**已验证的负结果——排除了什么，比确认了什么更有信息量**：
- 拼接诊断当前inlier比例仅约20%（原始匹配数充足但RANSAC筛选后所剩
  很少）。曾推测根因是ORB匹配未限定在真实几何重叠走廊内，全图匹配
  混入了非重叠区域的噪声匹配。专门诊断（导出`buildGroundProjectionMaps`
  实际算出的每路相机IPM有效区掩膜，与逐个ORB匹配点的坐标+RANSAC
  inlier/outlier标记对齐分析）**直接推翻了这一假设**：四个几何重叠较
  窄的相机对里，有三个的outlier落在理论重叠区内的比例反而**高于**
  inlier（如某对分别为7.0%/3.7%），方向与假设相反；重叠较宽的相机对
  里inlier/outlier落在重叠区内的比例也高度接近，没有出现假设预期的
  系统性分离。**排除了什么**：低inlier比例不是因为在非重叠区瞎匹配——
  限定匹配区域到几何走廊不会改善这个问题，不值得投入。**更可能的
  方向**：重叠区内部本身缺乏可靠特征，两个互不排斥的候选解释——(a)水面
  纹理重复/弱纹理，可匹配的稳定特征点本来就少；(b)平面单应模型对
  浮球、游动船只这类有真实高度的三维目标存在固有局限——BEV是把图像
  投影到地平面(z=0)的近似，具有高度的目标在两路BEV图像里的成像位置
  并不严格满足同一个单应变换，这是几何上的必然结果，不是特征提取或
  匹配策略能够消除的误差来源。若这一解释成立，也为拼接精度章节记录
  的pair(2,3)持续偏差最大这一观察提供了一个可能但未经验证的方向：
  该相机对覆盖的场景范围内若存在更多高度目标或更少可靠平面特征，
  会稳定地表现更差——这只是一个待后续验证的猜想，不作为结论。

**受限于传感器配置本身，算法层面难以根治**：
- 40m+的近端面效应与召回下降，根本原因是六路Airy雷达60m量程的物理
  边界——超出此距离只有forward雷达（窄视场120°×15°）继续覆盖，单一
  视角的近端面遮挡是任何被动式激光雷达感知的几何属性，不是聚类/分类
  算法能够单独消除的限制（多帧时序累积理论上能提供额外视角约束，但
  第4节多帧累积方案的历史评估结果本身也需要在新的方差认知下重新
  审视，见实验分析章节第2节）。
