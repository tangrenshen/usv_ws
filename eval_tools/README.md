# 评测工具链（2026-09-12 归档）

报告与答辩材料中的感知指标全部由本目录的脚本产出。归档在此，是为了让报告里的
每一个数字都能被重新跑出来；脚本按当时运行的原样保留，**内含绝对路径**
（`/home/lyf040817/bags_5run`、`/home/lyf040817/boatmiss` 等），换机器需改路径。

## 一、四类目标指标（遗漏率 / 误检率 / 分类错误率 / 位置误差）

| 脚本 | 作用 |
|---|---|
| `cap.sh` / `cap_all.sh` | 回放录制包并起感知节点，用**同一个录制器**接收四类真值、四类检测、odom 与融合点云 |
| `kill_rec.sh` | 清理残留录制器（后台进程屏蔽 SIGINT，必须 SIGTERM 并核实退出） |
| `cap2jsonl.py` | 录制包 → jsonl，所有记录的时间戳一律取录制器**接收时刻** |
| `../four_category_evaluator_v4.py --common-clock` | 在单一时钟下评估；口径与赛会 2026-09-02 答复一致 |
| `miss_window.py` | 按"周期内识别到一次即算识别到"统计遗漏率，窗口可扫（逐帧 / 1s / 5s / 整段） |
| `miss_pertest.py` | 周期=一次完整测试；分母 A=话题内全部目标，B=曾进入传感器覆盖范围的目标 |
| `align_check.py` | **对齐自检**：给真值或 odom 加偏移 Δ 扫描，命中率应在 Δ≈0 取峰、位置误差在 Δ≈0 取谷 |
| `obj_detail.py` | 逐目标明细（中位距离、是否识别到、是否在覆盖内），供绘图用 |

### 为什么必须用单一时钟

`four_category_evaluator_v3.py` 对真值 / 检测 / odom 三条流各按自身首末时刻线性
映射。检测流比真值流晚开始、早结束，被整体拉伸，中段错位数秒。静止目标几乎
不受影响，以约 1 m/s 运动的船只则大量落到 2 m 匹配容差外，被同时计为漏检与误检。
`v3_shift.py` 复现该缺陷（船只命中峰落在 Δ≈−3~−4 s），`v3_fixalign.py` 用纯偏移
对齐修正旧日志，`shift_scan.py` 在新录制上验证峰在 Δ≈0。v4 保留 v3 的全部口径，
只改时间映射。

## 三、鸟瞰图与融合

| 脚本 | 作用 |
|---|---|
| `cap_bev.sh` / `cmp_bev.py` | 鸟瞰图 A/B：与俯视相机逐像素比对（31.40 px/m 裁切、朝向变换只在基线上定一次、逐帧偏置对齐）。用于判定目标级归属渲染各模式，结论为无改善且小于同配置重复跑的噪声底 |
| `lidar_consistency.py` | 跨雷达一致性，点到点口径（**已弃用**：主要反映点密度，保留仅为效度自检的对照） |
| `lidar_plane_consistency.py` | 跨雷达一致性，面到面口径（现行）。用法：`python3 lidar_plane_consistency.py 3 0.5 10 <seed>` |

**2026-09-12 修复**：`lidar_plane_consistency.py` 原用 `abs(hash(name))%997` 决定
逐雷达扰动量，而 Python 字符串 hash 每进程带随机盐——同一 seed 每次运行的扰动
都不同，结果不可复现。改用 `zlib.crc32` 后确定可复现。修复前后报告口径的数字：
中位 0.17 m 不变，跨抽样区间由 0.17~0.34 m 修正为 0.06~0.50 m。

## 四、纪律

1. 任何跨时钟对齐，报数前先做偏移扫描自检（`align_check.py`），峰/谷必须在 Δ≈0。
2. 能出图的改动先看图再报标量——指标测的是"这里有没有东西"，不是"目标在不在"。
3. 后台进程用 SIGTERM 停止并用 `pgrep` 核实；SIGINT 在非交互 shell 里会被屏蔽。
4. 本目录是这些脚本的正式版本，后续修改请改这里的副本。
